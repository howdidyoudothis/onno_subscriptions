# Исходное тестовое задание — сервис подписок на onno

> Требования тестового задания.

От стажёра требуется разработка систем и их прототипов на основе фреймворка onno, поэтому тестовое задание представляет из себя разработку простого сервиса в вакууме с использованием фреймворка. Настоятельно рекомендуется использовать ИИ инструменты (cursor, codex, claude code), так как во время стажировки их использование будет обязательным для достижения необходимых сроков. Однако по реализации могут быть заданы вопросы, важно понимать, как работает система и как реализована функциональность. Реализация тестового задания должна занимать не дольше вечера.

## 1. Что необходимо

Разработать сервис учета и управления подписками клиентов на тарифные планы.

Документацию, а также скиллы, описания и maven пакеты можно найти в репозитории: https://github.com/onno-erp/onno-framework (просим ставить звезды).

Ключевое отличие от обычного CRUD-приложения на Spring: не надо вручную писать таблицы, DTO, контроллеры и формы. Хватает описания бизнеса на типизированной Java-метамодели. А схему БД, REST API, веб-интерфейс и историю миграций фреймворк генерирует сам.

## 2. Постановка задачи

Компания продаёт доступ к сервису по подписке.

- Клиент заводит лицевой счёт и пополняет его платежами.
- Клиент оформляет подписку на один или несколько тарифов. В одном документе подписки может быть несколько строк: каждая строка — тариф, купленный на N периодов.
- Стоимость подписки списывается с лицевого счёта в момент проведения документа.
- Оформить подписку при нехватке денег на счёте нельзя.
- Срок действия подписки — дата начала плюс максимальный срок среди строк документа. Тариф на 365 дней и тариф на 30 дней в одном документе дают подписку на 365 дней.
- Отменённая подписка не создаёт никаких движений: деньги не списываются, выручка не признаётся.
- Необходимая отчётность: текущие остатки лицевых счетов и выручка в разрезе тарифов и клиентов.

## 3. Основные сущности

| Сущность | Ключевые поля |
|---|---|
| Клиент | статус, e-mail, телефон, дата регистрации |
| Тариф | цена за период, длительность периода в днях, доступен ли для подключения |
| Платёж | клиент, сумма, способ оплаты |
| Подписка | клиент, статус, даты действия, итог, строки |
| Строка подписки | тариф, число периодов, цена, сумма |
| Статус подписки, статус клиента, способ оплаты | — |
| Лицевой счёт | измерения: клиент; ресурс: сумма |
| Выручка по тарифам | измерения: тариф, клиент; ресурсы: сумма, периодов |

## 4. Требования к заданию

### Уровень 1. Модель и интерфейс

- Справочники, перечисления, документы и табличная часть по таблице выше.
- `EntityView` для каждой сущности, которую видит пользователь: колонки списка, порядок и ширина полей формы, формат денег и дат, подсказки.
- `Layout` с разделами бокового меню.
- Приложение запускается, в интерфейсе можно завести клиента, тариф, платёж и подписку.

### Уровень 2. Бизнес-логика

- Регистры остатков и оборотов.
- Проведение: платёж пополняет лицевой счёт, подписка списывает с него и признаёт выручку.
- Отменённая подписка не создаёт движений.
- Бизнес-правила (`Validated` + `BusinessRule`): клиент обязателен, хотя бы одна строка, число периодов больше нуля, тариф доступен для подключения.
- Автоподстановка: дата документа и дата начала при создании; цена строки из тарифа; пересчёт сумм и даты окончания при каждом сохранении.
- Регламентное задание (`@ScheduledJob` + `BackgroundTask`): перевод подписок в статусы «Активна» и «Истекла» по датам.

### Уровень 3. Качество

- Обязательно покрыть код тестами, чтобы гарантировать соответствие бизнес правилам (бонус за трассировку).

## 5. Дополнительная функциональность (если хватает времени)

- Страница-дашборд (`Page`): показатели за период, диаграммы, последние документы.
- Действия в списке и на форме (`ActionSpec`): отмена подписки с указанием причины в модальном окне.
- Развернуть приложение на VPS.

## 6. Артефакты

Для сдачи тестового задания необходимо прислать ссылку на публичный репозиторий в GitHub. В репозитории должно быть представлено решение на Java, а также описание запуска и работы с приложением в `README.md`.
