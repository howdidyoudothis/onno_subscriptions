# Сервис подписок на onno

Отдельное Java-приложение: клиенты, тарифы, платежи, многострочные подписки, учёт остатков и выручки, фоновая смена статусов.

## Подготовка и сборка

Нужны Windows, PowerShell и установленная **Microsoft OpenJDK 21**. Стек: Java **21**, Gradle Wrapper **8.14**, Spring Boot **3.4.4**, onno **3.4.1**, H2 **2.3.232**. Gradle toolchain требует Java 21 с vendor Microsoft.

Откройте существующий проект в IntelliJ IDEA и PowerShell в корне репозитория. Укажите путь к своей установленной Microsoft JDK 21; это настройка только текущего процесса:

```powershell
$env:JAVA_HOME = 'C:\path\to\microsoft-jdk-21'
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
java -version
javac -version
.\gradlew.bat --version
```

В IntelliJ IDEA укажите Microsoft JDK 21 для Project SDK и Gradle JVM, Distribution — Wrapper.

Первая сборка требует доступа к репозиториям для загрузки Wrapper, плагинов и зависимостей:

```powershell
.\gradlew.bat --no-daemon clean test build
```

После загрузки можно повторять проверку без сети:

```powershell
.\gradlew.bat --offline --no-daemon clean test build
```

Интеграционные тесты используют настоящие Spring/onno beans и изолированную H2. Они проверяют денежные правила, откаты, конкуренцию, HTTP/права/CSRF, отчёт и реальное выполнение фонового задания. Рабочая файловая БД в тестах не используется.

Тесты документов сгруппированы по расчётам и валидации, проведению и откатам, HTTP и доступу. Отдельные тесты проверяют статусы, отчёт и фоновое задание. Фикстуры, HTTP/CSRF-поддержка и инъекция сбоев отделены от сценариев.

## Запуск и сохранение данных

Из того же корня, с указанной выше Java:

```powershell
.\gradlew.bat --offline --no-daemon bootRun
```

Альтернатива после сборки — исполняемый bootJar:

```powershell
java -jar .\build\libs\onno_subscriptions-1.0-SNAPSHOT.jar
```

Файл с суффиксом `-plain.jar` для этого запуска не предназначен. Откройте [интерфейс](http://127.0.0.1:8080/ui/). Локальный тестовый вход — **admin / admin**, роль ADMIN. Сервер слушает `127.0.0.1`, remember-me отключён.

Данные сохраняются в `data/subscriptions.mv.db`, URL — `jdbc:h2:file:./data/subscriptions`. Останавливайте запуск через **Ctrl+C**; при вопросе `Terminate batch job (Y/N)?` ответьте `Y`. Повторный запуск из того же корня использует тот же файл, после него войдите заново. Запускайте один экземпляр на один файл H2. В IDEA можно выполнить `bootRun` через Gradle Tool Window с рабочим каталогом в корне проекта.

## Демонстрация

1. В «Справочники → Клиенты» создайте клиента: имя, статус, e-mail, телефон. Дата регистрации заполняется автоматически; статус «Неактивен» сам по себе не запрещает операции.
2. В «Тарифы» создайте доступные A с ценой 100 и периодом 30 дней, B с ценой 250 и периодом 365 дней. Коды каталогов назначает onno.
3. В «Документы → Платежи» создайте платёж клиенту на 1000, выберите способ оплаты и нажмите «Записать». Черновик не пополняет счёт. Откройте сохранённую запись, в `More actions` выберите «Провести сохранённый документ». В «Учёт → Лицевые счета → Остатки» получится 1000.
4. В «Документы → Подписки» выберите клиента, добавьте строки A ×2 и B ×1. Укажите только тарифы и положительное целое число периодов. Нажмите «Записать»: сервер подставит дату документа и пустую дату начала, рассчитает цены 100/250, суммы 200/250, итог 450 и окончание через 365 дней. Пустое начало заменяется текущей датой Москвы; явно заданная дата сохраняется.
5. Проверьте рассчитанный черновик и отдельно проведите его через `More actions`. До проведения нет списания или активации; после него остаток — 550. Смена тарифа пересчитывает цену и срок после следующего сохранения. День окончания не входит в срок действия: `[start,end)`.
6. В «Учёт → Отчёт по выручке» нажмите «Сформировать», задайте даты финансовых движений включительно и, при необходимости, клиента. Результат — отдельная строка на клиент/тариф: A 200.00 / 2 периода, B 250.00 / 1 период. Пустой период сообщается явно. Отчёт доступен ADMIN и не меняет данные. «Выручка по тарифам» показывает историю отдельных активных движений.
7. Дополнительная подписка A ×1 даст остаток 450 и общий отчёт A 300.00 / 3, B 250.00 / 1. Её «Отменить подписку» вернёт остаток 550 и A 200.00 / 2. Отмена окончательна: CANCELLED повторно не проводится; отмена черновика не создаёт движений.

Нехватка средств, отсутствие клиента/строк, неположительное число периодов и недоступный тариф отклоняются. Проведённый документ нельзя финансово редактировать. Для исправления сначала «Снять проведение», затем изменить и сохранить черновик, проверить расчёт и отдельно провести. Снятие платежа отклоняется, если деньги уже потрачены. Каждая операция атомарна, вся последовательность исправления — несколько отдельных операций. Повторное проведение уже проведённого документа не создаёт второй финансовый эффект.

Деньги — `BigDecimal`, принимаются точно до двух дробных знаков без округления, максимум 13 целых цифр. Сохранённая строка хранит доверенные цену и длительность тарифа; последующее изменение справочника не переоценивает её. Штатные заголовки `New Subscriptions`, `Lines`, `More actions` местами английские; деловые поля и меню — русские.

## Фоновая смена статусов и устройство приложения

`SubscriptionStatusTask` — `BackgroundTask` с `@ScheduledJob`, запускается раз в минуту через JobRunr. До начала подписка WAITING, от начала до исключающего конца ACTIVE, в день конца EXPIRED. Один бизнес-день прохода берётся из Clock Europe/Moscow. Draft/deleted/CANCELLED пропускаются; EXPIRED остаётся проведённой и сохраняет выручку. Задание меняет только статус, без переоценки строк и денежных движений; ошибки видны в логах. Worker включён, один исполнитель, dashboard выключен.

Аннотации задают метамодель и права, onno создаёт схему, CRUD и формы. `EntityView` задаёт представление и действия, `Layout` — меню. Lifecycle сохранения считает суммы и срок и проверяет правила. Узкое расширение штатных команд обеспечивает транзакцию общего DataSource, блокировку документа и финансовые guards; движения выполняет штатный PostingEngine. Остатки и отчёт читаются из регистров, отдельного баланса в клиенте нет. Собственные CRUD-контроллеры, DTO, DDL, миграции и frontend не добавлены.

## Состав проекта

Для сборки нужны исходники `src/`, Kotlin DSL build/settings и полный Gradle Wrapper, включая `gradle-wrapper.jar`. `reference/`, `.gradle/`, `.idea/`, `build/` и локальные БД не нужны в исходной поставке и исключены из Git. Тесты не зависят от игнорируемых исследовательских файлов.

Требования описаны в [тестовом задании](docs/assignment.md). Приложение предназначено для прототипа на H2; интерфейс и отчёт используются под ролью ADMIN.
